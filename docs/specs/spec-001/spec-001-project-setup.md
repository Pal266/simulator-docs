# Project setup

## Type

`feature`.

## Requirements

1. Create `pom.xml` in the application repository root. Configure Apache Maven to compile and package the application using JDK 25 with Java release 25. Use only the Java standard library for this setup.
2. Configure a Maven command that launches the application's current entry point from the project root. IntelliJ IDEA must be able to import the root POM and build and launch the same entry point using JDK 25 and the Java release declared in the POM.
3. Update the root `README.md`, creating it if missing. Make the first numbered step a copyable `git clone` command using the actual application repository URL. Show how to enter the cloned directory and identify the required tools, compatible versions, and any environment settings needed for each workflow.
4. Document two workflows after the shared clone step. For the command-line workflow, give the exact Maven commands to build and run. For the IntelliJ IDEA workflow, identify what to open, how to import the Maven project, which JDK to select for the project and Maven, and which IDE actions or run configuration to use to build and launch. Include any required arguments or working directory and describe the observable result of a successful launch in the application's current state.

## Acceptance criteria

- Starting from a fresh clone and following the command-line instructions in order produces the application artifact and launches the documented entry point with the stated observable result.
- Starting from a separate fresh clone and following the IntelliJ IDEA instructions produces a successful build and the same observable launch result without depending on files generated by the command-line walkthrough.
- The root POM targets Java release 25 and declares zero external project dependencies.
- The root README begins its procedure with the application repository's working clone command. A developer can complete either workflow using the settings and steps provided there.
