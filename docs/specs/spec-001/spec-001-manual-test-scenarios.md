# Manual test scenarios for project setup

R1–R4 and AC1–AC4 refer to the requirements and acceptance criteria in their listed order. Record the reviewed application commit, IntelliJ IDEA version, and JDK version with the evidence.

| Number | Test scenario | Workflow | Result | Conclusion |
|---|---|---|---|---|
| 1 | **Follow the README in IntelliJ IDEA from an independent clone.** R2–R4, AC2, AC4. A tester must follow the written IDE actions and judge whether they identify the settings and controls needed to launch the app. | 1. Start with Git, JDK 25, the documented IntelliJ IDEA version, and any other prerequisites listed for the IDE workflow. Use a new empty parent directory named `IDE Setup Check`. 2. Follow the README clone and directory steps. For an unmerged change, check out the reviewed revision before opening the project. Do not run the Maven CLI build or copy local IDE settings or build output from another checkout. 3. Using only the README, open the indicated project or POM, import the Maven project, and set the project and Maven JDKs. 4. Follow the documented IDE build and run actions, including any arguments and working directory. 5. Compare the launch with the README's stated result and the Maven run at the same revision. If the expected result is visual, inspect both launches. | The README identifies the prerequisites, versions, settings and UI actions needed without guessing a missing step. IntelliJ imports the root Maven project, uses JDK 25 and Java release 25, builds successfully, and launches the same application entry point with the same documented observable result as Maven. Record the Maven project name, resolved JDK and release settings, build result, entry point, and observed launch result. Capture the Run window showing the launch and output or, for a graphical result, the documented visible state from each launch. If blocked, record the first missing or incorrect instruction and the UI state where progress stopped. | |
